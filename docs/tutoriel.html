Guide d'utilisation

Du premier lancement à la livraison d'un projet complet.

Étape 1 — Prérequis

  • Windows 10 ou 11
  • Claude Max (abonnement Anthropic)
  • Python 3.14+
  • Git for Windows
  • Antigravity IDE (fork VS Code)
  • Obsidian avec plugin Local REST API activé

Étape 2 — Lancer l'environnement

# Mode complet (Graphify + pipeline complet)
cd "C:\Users\caste\Desktop\Espace_Opti"
.\full.ps1

# Mode rapide (session courte)
.\lite.ps1
💡 TIP — full.ps1 affiche l'URL du dashboard au démarrage et vérifie tous les composants.
⚠️ WARN — Obsidian doit être ouvert avant de lancer le script pour que le MCP obsidian fonctionne.

Étape 3 — Créer un nouveau projet

# Dériver un projet depuis le template
.\new-project.ps1 "MonProjet"

# Naviguer et lancer
cd "C:\Users\caste\Desktop\MonProjet"
.\full.ps1
💡 TIP — Nom valide : alphanumérique + tirets uniquement. Exemples : SaaS-RH, MailFlow, WebApp-Client.
⚠️ WARN — Ne jamais modifier les fichiers dans Espace_Opti/ directement. C'est le template maître.

Étape 4 — Orchestrer un projet complet

Dans Antigravity (Claude Code), la commande la plus puissante :

/run-project Je veux créer une app de gestion de factures pour PME

Ou invoquer directement le manager :

@manager Je veux créer une application SaaS de gestion RH
💡 TIP — Donne une description précise — le manager posera 8 questions de toute façon, mais une bonne description donne le contexte initial.
⚠️ WARN — Attends toujours la question "Valides-tu ce PRD ?" avant de continuer. Ne force pas le processus.

Étape 5 — Invoquer les agents directement

@architecte   → Décompose le PRD en modules + contrats
@frontend     → Implémente les modules UI owner:frontend
@backend      → Implémente les modules API owner:backend
@qa-review    → Audite le dernier module DONE
@simplifier   → Nettoie le code après approbation QA
@playwright   → Lance les tests E2E sur le PRD
@manager      → Orchestre tout de A à Z
💡 TIP — @frontend et @backend tournent en isolation git worktree. Tu peux les lancer simultanément dans deux sessions Antigravity.
⚠️ WARN — @securite s'active automatiquement via hook PreToolUse. Ne jamais l'invoquer manuellement.

Étape 6 — Slash commands

CommandeUsage
/run-project [idée]Orchestration complète via @manager
/start-prd [idée]PRD interactif (8 questions)
/new-module [nom]Développer un module spécifique
/deliverPipeline de livraison complet
/dashboardLance le monitoring web
/start-feature [desc]Workflow feature avec contexte mémoire

Étape 7 — Dashboard web

# Depuis Espace_Opti (ou n'importe quel projet dérivé)
python dashboard.py
# → Ouvre automatiquement http://localhost:3131

Le dashboard permet :

  • Voir tous les projets avec leur progression (barre)
  • Kanban drag-and-drop des modules (TODO / IN_PROGRESS / DONE / APPROVED)
  • Éditer PRD.md, modules.json, CLAUDE.md dans le navigateur
  • Voir les logs des agents en temps réel via WebSocket
  • Lancer full.ps1, lite.ps1, sync_memory.py depuis l'interface

Étape 8 — Synchroniser la mémoire Obsidian → Pinecone

python sync_memory.py
# → Vectorise les notes Obsidian dans Pinecone
# → Rapporte : X files, Y chunks, Z vectors total
💡 TIP — Lance après chaque session importante de documentation ou de création d'ADR.
⚠️ WARN — Obsidian doit être ouvert et le plugin Local REST API activé.

Étape 9 — Livraison du projet

/deliver

Résultat attendu :

✅ Output :
DEPLOYMENT.md généré  ·  Note Obsidian ADR créée  ·  git tag v1.0.0 créé
Puis : 🛑 "Valides-tu le git push ?" ← tu réponds "valide"

Exemple complet — Gestion de factures PME

Voir l'exemple complet de A à Z (cliquer pour développer)

1. Lancement

.\new-project.ps1 "FacturePME"
cd C:\Users\caste\Desktop\FacturePME
.\full.ps1

2. Orchestration

/run-project Application de gestion de factures pour PME :
clients, produits, factures, export PDF, relance auto

3. PRD (@manager pose 8 questions)

→ Génération PRD.md · 🛑 validation utilisateur

4. Architecture (@architecte)

{
  "modules": [
    { "id": "auth-backend",     "owner": "backend",  "status": "TODO" },
    { "id": "clients-backend",  "owner": "backend",  "status": "TODO" },
    { "id": "factures-backend", "owner": "backend",  "status": "TODO" },
    { "id": "clients-frontend", "owner": "frontend", "status": "TODO" },
    { "id": "factures-frontend","owner": "frontend", "status": "TODO" },
    { "id": "pdf-export",       "owner": "backend",  "status": "TODO" }
  ]
}

5. Développement parallèle

@frontend et @backend travaillent en worktrees isolés. @securite scanne chaque écriture.

6. Validation QA → Simplification → Tests E2E → Livraison

Tag v1.0.0 créé, ADR dans Obsidian, sync_memory.py lancé. 🛑 validation git push.
