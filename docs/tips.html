Tips, Limites & Problèmes Connus

Tout ce qu'on aurait aimé savoir dès le départ.

Tips avancés

💡 TIP 1 — Mémoire persistante des agents
La mémoire dans .claude/agent-memory/<nom>/ s'accumule au fil du temps. Plus tu utilises un agent, plus il devient performant sur ton style de projets. Consulte .claude/agent-memory/manager/MEMORY.md pour voir ce que le manager a appris.
💡 TIP 2 — Parallélisme @frontend + @backend
Ces deux agents ont isolation: worktree — ils travaillent sur des copies git isolées. Lance-les dans deux fenêtres Antigravity simultanément sans risque de conflit de fichiers.
💡 TIP 3 — Bypass sécurité légitime
Si @securite bloque du code légitime (faux positif), ajoute en fin de ligne : 
result = md5(config_key)  # security-ok: not a password hash
💡 TIP 4 — Coût réel = 0 € supplémentaire
Claude Max = usage illimité. Embeddings = locaux (all-MiniLM-L6-v2). Pinecone = tier gratuit (1 index, 100k vecteurs). Obsidian = gratuit. Graphify = gratuit.
💡 TIP 5 — new-project.ps1 reset automatique
Chaque nouveau projet repart avec .claude/agent-memory/ vide — les agents apprennent projet par projet, indépendamment.
💡 TIP 6 — git worktree et isolation
Les worktrees des agents @frontend et @backend sont nettoyés automatiquement s'ils ne produisent aucun changement. En cas de résidu : git worktree prune.
💡 TIP 7 — Recharger les agents sans redémarrer
Si tu modifies un fichier dans .claude/agents/, tape /agents dans Claude Code pour recharger sans fermer Antigravity.
💡 TIP 8 — claude-mem capture tout automatiquement
Le plugin claude-mem (officiel, installé via npx claude-mem install) capture automatiquement toutes les mémoires des agents. Consulter l'UI sur http://localhost:37777 ou utiliser /mem-search "query" dans Claude Code pour chercher dans l'historique.
💡 TIP 9 — /loop pour tâches récurrentes
La slash command /loop fait tourner @manager sur un intervalle fixe jusqu'à 72h maximum. Pratique pour monitoring de build, polling de déploiement, ou vérifications périodiques : 
/loop 30m verifier que les tests passent toujours
/loop 1h  surveiller le build et alerter si echec
Chaque itération est capturée automatiquement par claude-mem. Stop automatique après 3 échecs consécutifs.
💡 TIP 10 — Workflow 3 couches mémoire dans les agents
Tous les agents (manager, architecte, frontend, backend, qa-review, simplifier, playwright) consultent leur mémoire en 3 passes : index rapide (50 tokens) → timeline filtrée → détails à la demande via /mem-search. Évite de charger toute la mémoire pour chaque tâche.

Tips Boris Cherny (intégrés 2026-04-17)

💡 TIP 12 — Commit automatique par phase
Le @manager propose maintenant un git commit descriptif après chaque phase du pipeline 7 phases validée par l'utilisateur (conventional commit). Avoir un point de restauration par phase permet de revenir en arrière facilement. Source : Boris Cherny — « commit au moins 1x par heure ».
💡 TIP 13 — Rewind plutôt que corriger
Si Claude part dans la mauvaise direction, ne pas essayer de corriger dans la même session (le contexte est déjà pollué). Solutions rapides :
  • Appuyer 2× sur Escape pour annuler le dernier changement
  • Taper /rewind pour revenir à un checkpoint antérieur
Évite de brûler des tokens à corriger une session qui déraille.
💡 TIP 14 — Compact manuel à 50% max
Pour éviter la « agent dumb zone » (dégradation de Claude en fin de contexte), faire /compact manuellement dès que le contexte atteint 50%. Ne pas attendre l'auto-compact qui intervient trop tard. Source : Boris Cherny.
💡 TIP 15 — Screenshots pour debugging
Quand bloqué sur un problème visuel ou UI :
  • Prendre un screenshot avec Windows + Shift + S
  • Coller directement dans le chat Claude Code avec Ctrl + V
  • Claude voit l'image et peut analyser le problème
Bien plus efficace que décrire le problème en texte.
💡 TIP 16 — /status pour suivi rapide
Taper /status à tout moment pour afficher l'état complet du workspace : modules.json, phase courante, dernier commit, fichiers non committés, budget tokens, agents actifs, santé claude-mem. Sans interrompre le flux de travail.
💡 TIP 17 — Diagrammes ASCII dans l'architecture
L'@architecte génère systématiquement un diagramme ASCII dans ARCHITECTURE.md montrant les modules, leurs dépendances et les flux de données. 
+-------------+       +-------------+
|  Frontend   | <---> |   Backend   |
|  React      |  API  |  FastAPI    |
+-------------+       +-------------+
                            |
                            v
                      +-------------+
                      |  Postgres   |
                      +-------------+
Les diagrammes ASCII sont plus efficaces pour Claude que les descriptions textuelles, et ne nécessitent aucune dépendance externe.

Limites connues

⚠️ LIMIT 1 — Contexte ~200k tokens par session
Claude Max offre un contexte d'environ 200k tokens. Pour de très gros projets, divise le développement en plusieurs sessions ou utilise /new-module module par module.
⚠️ LIMIT 2 — Parallélisme = sessions manuelles
Le vrai parallélisme @frontend + @backend nécessite deux sessions Antigravity manuelles. Dans une session unique, @manager les lance séquentiellement par défaut.
⚠️ LIMIT 3 — Pinecone tier gratuit
1 index, 100k vecteurs max. Suffisant pour des dizaines de projets. Si tu dépasses : supprimer les vieux vecteurs ou upgrader vers un tier payant.
⚠️ LIMIT 4 — Obsidian doit être ouvert
Le MCP Obsidian ne fonctionne que si l'application Obsidian est lancée. Un hook de démarrage automatique est prévu pour la prochaine version.
⚠️ LIMIT 5 — @securite : faux positifs possibles
L'agent haiku sur 500 tokens peut bloquer du code de configuration ou de test légitime. Utilise # security-ok: raison pour bypass ponctuel.
⚠️ LIMIT 6 — Graphify sur gros projets
Graphify v0.4.2 peut être lent sur des codebases > 10k lignes. Le hook PreToolUse sur Glob/Grep peut ralentir les recherches.

Problèmes connus & solutions

❌ PROBLEM 1 — "Les agents ne sont pas détectés"
Cause : Claude Code nécessite un redémarrage pour charger les nouveaux agents.
✅ FIX — Dans Claude Code : taper /agents, ou fermer/rouvrir Antigravity.
❌ PROBLEM 2 — "sync_memory.py échoue (UnicodeDecodeError ou BOM)"
Cause : .env sauvegardé avec BOM UTF-8 (éditeur Windows).
✅ FIX 
python -c "
p=open('.env','rb'); d=p.read(); p.close()
open('.env','wb').write(d.lstrip(b'\xef\xbb\xbf'))
print('BOM removed')
"
❌ PROBLEM 3 — "Obsidian MCP : connexion refusée (WinError 10061)"
Cause : Obsidian non ouvert ou plugin Local REST API désactivé.
✅ FIX — Ouvrir Obsidian → Settings → Community Plugins → Local REST API → Enable. Vérifier le port : 27124.
❌ PROBLEM 4 — "Port 3131 déjà utilisé"
Cause : Instance du dashboard déjà en cours d'exécution.
✅ FIX 
taskkill /F /IM python.exe
python dashboard.py
❌ PROBLEM 5 — "@securite bloque du code légitime"
Cause : Faux positif sur pattern OWASP.
✅ FIX — Ajouter en fin de ligne concernée : # security-ok: raison de la dérogation
❌ PROBLEM 6 — "git worktree error: already exists"
Cause : Worktree résiduel d'une session précédente (bug Claude Code v2.1.x).
✅ FIX 
git worktree prune
# puis relancer l'agent
❌ PROBLEM 7 — "modules.json mal formé après drag-and-drop"
Cause : Race condition entre WebSocket et sauvegarde fichier.
✅ FIX — Rafraîchir le dashboard (F5) et refaire le drag-and-drop.
