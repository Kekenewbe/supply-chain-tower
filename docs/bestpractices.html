Section 9 — Mémoire persistante (écosystème claude-mem)

Plugin Claude Code global — installé via npx claude-mem install. 5 composants techniques, 5 hooks de cycle de vie, 4 outils MCP, 7 skills auto-installés.

9.1 — Vue d'ensemble

claude-mem est un plugin Claude Code installé globalement qui capture automatiquement toutes les actions des agents, sans configuration par projet. Il combine une base SQLite locale (observations + FTS5 plein-texte), un index vectoriel Chroma pour la recherche sémantique, et une UI web sur http://localhost:37777. Tous les projets dérivés d'Espace_Opti en bénéficient sans action supplémentaire.

9.6 — Privacy et contrôle

  • Tags <private> dans un message = contenu non stocké dans la mémoire claude-mem ni vectorisé dans Pinecone (sync_memory.py supprime aussi les blocs <private> avant vectorisation).
  • Citations par IDs — chaque observation est accessible via http://localhost:37777/api/observation/<ID>.
  • UI web — http://localhost:37777 — trois onglets : All (tout), Claude (Claude Code), Codex (OpenAI Codex / autre runtime).
  • Migration — les anciens fichiers memory_worker.py et memory_db.py (SQLite maison) ont été remplacés par claude-mem. Installation globale = zéro configuration par projet.

Section 10 — Prompt Engineering

Source : documentation officielle Anthropic (platform.claude.com).

Principes fondamentaux

  • Clarté avant tout — Claude est comme un employé brillant sans contexte. Plus tu es précis, meilleur est le résultat. Règle d'or : montre ton prompt à quelqu'un qui n'a pas ton contexte ; si cette personne est confuse, Claude le sera aussi.
  • Instructions séquentielles — utiliser des listes numérotées pour décrire les étapes à suivre.
  • Contexte et motivation — expliquer pourquoi la tâche doit être faite, pas seulement quoi faire. Le pourquoi guide les décisions dans les cas non explicités.

Techniques avancées

TechniqueQuand l'utiliserExemple
Balises XMLPrompts complexes avec sections multipleswrapper <instructions> <contexte> <exemples>
Few-shot examplesFormat ou style critique3 à 5 exemples dans <examples>
Rôle et personaToujours pour les agents spécialisés« Tu es un expert backend spécialisé en API REST et sécurité OWASP »
ultrathinkDécisions critiques ou complexesAjouter ultrathink en tout début de prompt
Long contextDocuments > 20k tokensPlacer les données longues en haut du prompt, instructions en bas

Agent @optimiseur dans Espace_Opti

  • Agent dédié à l'optimisation des prompts avant envoi aux autres agents.
  • Invocation : dire « optimise ce prompt » ou « améliore ce prompt ».
  • Modèle : sonnet — bon rapport qualité / vitesse.
  • Workflow : prompt brut → analyse des faiblesses → version améliorée → validation utilisateur → écriture dans inbox.md du projet cible via write-inbox.ps1.
  • Techniques appliquées : clarté, XML, exemples, rôle, critères de succès, ultrathink.
  • Mémoire persistante : .claude/agent-memory/optimiseur/ (workflow 3 couches identique aux autres agents).

Outils Anthropic disponibles

  • Prompt generator — platform.claude.com/dashboard — résout le problème de la page blanche, génère un premier draft.
  • Console Anthropic — platform.claude.com — test et itération de prompts, évaluation, variables.
  • Prompt templates — séparent contenu fixe et contenu variable via {{variable}}.

Erreurs courantes à éviter

⚠️ Prompt vague — « améliore ce code » → préférer « ajoute la validation des inputs dans la fonction login de auth.ts selon les règles OWASP ».
⚠️ Pas de format spécifié — toujours spécifier le format de sortie attendu (JSON, liste, tableau, markdown, diff…).
⚠️ Trop long et non structuré — au-delà de 200 lignes, utiliser impérativement les balises XML pour organiser le prompt.
⚠️ Pas d'exemples — pour les formats complexes, fournir 1 à 3 exemples avant la tâche réelle (few-shot).
⚠️ Micromanager les étapes — donner le but et les contraintes, pas les étapes exactes. Les agents trouvent le chemin eux-mêmes.

Règles critiques wrappées <important if="...">

  • if="writing code or calling tools" — interdits hard : pas de clé API en clair, pas de git push non validé, pas de modification directe d'Espace_Opti, pas de suppression de worktrees.
  • if="consulting or updating agent memory" — consultation 3 couches obligatoire (index → timeline → détails).
  • if="starting a new project or module" — respecter l'ordre des 7 phases, ne jamais skip la validation utilisateur.
💡 Pourquoi <important if="..."> — Les balises important conditionnelles empêchent Claude d'ignorer les règles quand le fichier CLAUDE.md grossit. Attention sélective déclenchée par le contexte d'exécution. Source : Dex (HumanLayer).

Ce qu'on a explicitement exclu

⚠️ Jamais ajouté aux permissions — Bash(rm*), Bash(git push*), Write(.env*). Ces wildcards sont trop dangereux même en mode wildcards. Boris préfère la liste explicite au blanket dangerously-skip-permissions.
