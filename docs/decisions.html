Arbre de décision

Formats de communication

NIVEAU 1 — Invisible

Le manager agit seul. L'utilisateur ne voit rien. Exemple : correction d'une erreur mécanique détectée par @securite, mise à jour de modules.json après un changement de statut.

NIVEAU 2 — Alerte informative

⚡ [MANAGER] Module auth-backend — QA échoué 2x (score 72/100)
   Action : Je renvoie au Backend avec les corrections.
   Je te tiens informé.

NIVEAU 3 — Décision requise

🛑 [MANAGER] Décision requise
   Situation : PRD.md généré et prêt pour validation
   Action attendue : Réponds "valide" pour continuer
   Résumé : [5 points clés du PRD]

Règles dures (jamais de dérogation)

  • Ne jamais pousser sur git sans validation explicite utilisateur
  • Ne jamais modifier les contrats d'interface sans repasser par @architecte
  • Ne jamais supprimer de fichiers sans confirmation
  • Toujours mettre à jour modules.json après chaque changement de statut
  • En cas de doute sur le niveau → toujours choisir NIVEAU 3
