Pipeline de Développement

7 phases orchestrées par @manager — de l'idée à la livraison.

🟢 NIVEAU 1Manager gère seul
🟡 NIVEAU 2Manager agit + informe
🔴 NIVEAU 3Attend décision utilisateur

Déclenchement

.\new-project.ps1 "MonProjet"
cd MonProjet
.\full.ps1
# Puis dans Claude Code :
/run-project "description du projet"

Phase 1 — PRD

Agent : @manager + skill prd-generator    🔴 NIVEAU 3

Input : idée libre de l'utilisateur
Output : PRD.md structuré
Process : reformulation → 8 questions → génération

Validation : "Voici le PRD généré. Valides-tu avant que je lance l'architecture ?"

Phase 2 — Architecture

Agent : @architecte (opus)    🔴 NIVEAU 3

Input : PRD.md validé
Output : modules.json + ARCHITECTURE.md
Process : domaines → modules → DAG → contrats d'interface immuables

Validation : "Voici ARCHITECTURE.md et modules.json. Valides-tu avant le dev ?"

Phase 3 — Développement parallèle

Agents : @frontend + @backend + @securite    🟢 NIVEAU 1

Input : modules.json + ARCHITECTURE.md
Output : code source /src/
Process : TDD (backend RED → GREEN → REFACTOR) et moodboard → composants (frontend)

💡 Isolation — Les deux agents travaillent en git worktree séparé. @securite scanne chaque écriture via hook PreToolUse (500 tokens max, haiku).

Phase 4 — Validation QA

Agent : @qa-review (opus)    🟡 NIVEAU 2 / 🔴 NIVEAU 3

Input : git diff du module
Output : REVIEW_REPORT.md + score /100

  • Score ≥ 80 → ✅ APPROUVÉ → @simplifier
  • Score 70-79 → 🔄 retour agent d'origine (NIVEAU 2)
  • Score < 70 → 🔄 retour @architecte (NIVEAU 2)
  • 3ᵉ échec → ⛔ NIVEAU 3 (décision utilisateur)

Phase 5 — Simplification

Agent : @simplifier (sonnet)    🟢 NIVEAU 1

Input : REVIEW_REPORT.md
Output : code nettoyé (−X LOC)
Invariant absolu : tests verts AVANT et APRÈS chaque modification. Rollback immédiat si un test casse.

Phase 6 — Tests E2E

Agent : @playwright (sonnet) + MCP Playwright    🔴 si fail

Input : user stories du PRD.md + application en cours d'exécution
Output : TEST_REPORT.md + screenshots screenshots/YYYY-MM-DD/
Règle dure : 1 test en échec = livraison BLOQUÉE, sans exception.

Phase 7 — Livraison

Agent : @manager    🔴 NIVEAU 3

Output : DEPLOYMENT.md + note Obsidian ADR + git tag v1.0.0

  1. Génération DEPLOYMENT.md
  2. Création note ADR dans le vault Obsidian
  3. Lancement sync_memory.py (Pinecone)
  4. Rebuild du graphe Graphify
  5. git commit + git tag v1.0.0
Validation finale : "Tous les tests sont verts. Valides-tu le git push ?"

Gestion du contexte

Agent : @estimateur (haiku)    Automatique

Surveillance continue du % de contexte utilisé pendant le développement. Objectif : utiliser 95-98% du contexte sans dépassement.

  • 70% — @estimateur invoqué automatiquement, propose 3 options pour maximiser l'usage
  • 75% — NIVEAU 2 : termine le module en cours, prépare la clôture
  • 85% — NIVEAU 3 : séquence de clôture automatique

Séquence de clôture (lancée à 85%)

  1. git add -A + git commit "chore: sauvegarde session"
  2. Mise à jour de modules.json (statuts exacts)
  3. Note Obsidian decisions/YYYY-MM-DD-session.md
  4. Lancement sync_memory.py
  5. Génération _workspace/resume-prompt-YYYY-MM-DD.md
